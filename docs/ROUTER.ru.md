# Flint 2: рабочее подключение

Обзор типового развёртывания FLR на GL.iNet Flint 2 (GL-MT6000) с OpenWrt 25.12.
Конкретные значения (адреса, пароли, имена сетей) задаёт владелец и в репозиторий
не попадают.

| Параметр | Значение |
|---|---|
| LuCI | `http://<адрес роутера>` / `https://<адрес роутера>` |
| SSH | `root@<адрес роутера>`, вход по ключу |
| LAN | адрес и префикс читаются из `br-lan`, DHCP |
| WAN | `eth1`, DHCP или настройки провайдера |
| Сервер | `203.0.113.10`, `vpn.example.com` |
| DNS LAN | `flr-controller` на 53, локальный dnsmasq на 1053 |
| LAN IPv6 | RA/DHCPv6 и forwarding выключены |
| Автозапуск | `flr-runtime`, `flr-proxies`, AWG netifd |

Подключите кабель провайдера к WAN Flint, домашние устройства — к LAN или Wi-Fi
Flint. Для проверки VPN подключитесь к сети самого Flint и отключите отдельный
клиентский VPN на проверяемом устройстве.

```sh
ssh root@<адрес роутера>
flr-controller status --json
```

## Проверки

Для приёмки проверяются: TCP и UDP по каждому каналу, failover AWG → Hysteria2,
сохранение живых соединений при восстановлении AWG, VPN/direct DNS, временный SOCKS
и его истечение/перезапуск. All-down закрывает VPN-класс, сохраняет direct и
локальный DNS. WAN capture не должен показывать VPN DNS/трафик напрямую. Защита
действует и до старта контроллера. Роутер и VPS должны переживать перезагрузку
без ручных действий.

Скорость зависит от маршрута и стенда; это не обещание гигабита и не измерение
игрового RTT.

## Восстановление после перезагрузки VPS

Flint возвращает канал после 60 s успешных TCP/UDP-проверок. При недоступности
всех каналов интернет через VPN временно закрыт, direct-исключения продолжают
работать. Состояние и выбранный канал: `flr-controller status` на роутере.

## Резервные копии и recovery

Перед установкой образа сохраните полный `/etc`, sysupgrade backup, загрузочные
разделы (bootloader, environment, factory, FIP, GPT) и прежние kernel/rootfs в
приватное место вне Git, с ограниченными правами. На Flint `/etc/flr-runtime/backup`
содержит исходные network/firewall/dhcp для runtime rollback.

Runtime не изменяет raw partitions или Web Recovery. При восстановлении
используйте штатную recovery-процедуру GL.iNet, а не непроверенную запись
сохранённых raw dumps.
