# Управление подключениями FLR

Документ описывает новую версию, которую готовим для финального образа. Проверка этой версии на роутере выполняется только после снятия запрета на накат; успешные CI-проверки не заменяют hardware acceptance.

## Страница «Прокси»

Все AWG и proxy-конфиги управляются на одной странице. Подключение имеет постоянный ID, имя, группу/VPS, протокол, состояние enabled и revision конфигурации. Метаданные можно менять отдельно от полного конфига; замена endpoint сохраняет ID и создаёт новую revision. Измерения другого VPS или прежней revision не используются для нового подключения.

Режимы:

- **Авто** — выбирает доступное подключение по установленному порядку, переключается при отказе.
- **Только протокол** — использует подключения выбранного семейства, например AWG; другие семейства автоматически не включаются.
- **Конкретное подключение** — сохраняет выбранный ID, даже если он недоступен. Скрытого fallback нет.

Порядок задаётся отдельно для протоколов и подключений внутри каждого протокола. Изменение порядка само по себе не перезапускает исправное подключение. Для применения нового предпочтения сразу используется явная опция повторного выбора. При удалении pinned-подключения нужно явно выбрать переход в «Авто».

Фактический активный путь отображается отдельно от запрошенного режима и pending. Успешное сохранение настройки не доказывает, что подключение уже работает. Подключения с отсутствующим компонентом остаются видимыми с причиной недоступности.

## Импорт и замена

Принимаются поддержанные URI, JSON, base64-подписки, строгие AWG-файлы и смешанные JSON-массивы строк. Ошибка хотя бы одного элемента отклоняет весь импорт; частичного сохранения нет. Секреты полного конфига не возвращаются в public API и не включаются в firmware.

Для LuCI data/file импорта проверяется полный UTF-8 HTTP JSON-RPC конверт: максимум 65 536 байт, включая служебные поля. Размер исходного файла не равен допустимому размеру запроса. Слишком большой запрос отвергается до отправки с понятной ошибкой. HTTPS URL использует отдельное серверное чтение с пределом 1 МиБ и ограничением времени; это не увеличение HTTP лимита.

В AWG-файле поддержан один `Table=off` только в `[Interface]`. Директива не передаётся в native network config: маршрутизацией управляет FLR. Произвольные Table, повторные поля, hooks и ссылки на файлы отвергаются.

«Проверить подключение» выполняет реальную временную проверку TCP/UDP, может переключить рабочий путь и нарушить существующие сессии. Результат появляется асинхронно. Watchdog восстанавливает принадлежащее тесту намерение; новый ручной выбор имеет приоритет. Восстановление режима не означает восстановления уже прерванной игровой сессии. При ошибке восстановления причина остаётся видимой, обычная автоматика не запускается поверх незавершённого recovery.

## Сохранение сессий при возврате AWG

Согласованное дополнение. Новый образ должен сохранять один работающий proxy-резерв при квалифицированном восстановлении AWG. Новые соединения возвращаются на более приоритетный AWG; старые TCP/UDP сохраняют conntrack-привязку и прежний backend. Повторный отказ AWG использует готовый резерв без перезапуска. Менеджер сохраняет резерв, а kernel-квалификация production-правил выполняется перед выпуском. Её результат ещё требуется; проверка реальных туннелей и устройства остаётся отдельной приёмкой.

Поддержание двух каналов не дублирует пользовательский трафик. Это один native AWG и один imported backend, а не запуск всех профилей. Смена между двумя AWG endpoint или между proxy-профилями в одном слоте может нарушить сессии; она не обещается бесшовной. Прямого WAN fallback для VPN-трафика нет.

## Сборка и проверка

Sing-box1.14.2 строится из закреплённых исходников Go1.26.8 с CGO=0 и QUIC/WireGuard/uTLS/gVisor tags (gVisor необходим для production WGWS). `ci/build-sing-box.py` работает только в disposable Linux AMD64 GitHub Actions. Upstream Makefile и `@latest` инструменты не запускаются. Проверяются архив исходников, точные go.mod/go.sum, реальные embedded build settings и linked modules обеих статических целей.

Перед упаковкой matching AMD64 engine проверяет настоящие конфиги production renderer. Resolver сохраняет custom source provenance и не подменяет отсутствующую или не прошедшую проверку сборку официальным prebuilt. SDK получает проверенные binary/LICENSE; пакет и rootfs должны сохранять их SHA. Proxy JS и CSS обязательны в проверяемом runtime root.

Финальный workflow дополнительно проверяет controller race/vet, LuCI, Python guards, AWG UAPI/kernel ABI, подписи пакетов, отсутствие приватных конфигов и состав sysupgrade. В receipts различаются source/native/kernel проверки и фактическая приёмка на устройстве.

Для дополнительных CI-зависимостей действует отдельное согласование владельца; обычный push в main не запускает image build. Артефакты готовятся без изменения установленного на роутере контроллера.

## Диагностика переключений

Статус отделяет фактический маршрут новых соединений от желаемого выбора и сохранённого proxy-слота. Ошибка применения nft не превращает желаемый AWG в фактически применённый путь. Журнал содержит подготовку и реальный исход операций с nft, conntrack, native-подключением и процессом; ручной тест фиксирует начало и завершение. При неуспешной операции сохраняется причина и ожидание повтора.

История держит максимум720 раундов и256 решений, не более4МиБ сериализованных подготовленных полей. Private0600 снимок пишется только в RAM /var/run/flr-runtime; ключи, конфиги, stdout/stderr native-команд и домены клиентов в схему не входят. После перезапуска службы начинается новая история. Раздельная WAN-диагностика не выбирает маршрут и не блокирует VPN-пробы. Read ACL разрешает сводку, расширенный экспорт требует write ACL и использует страницы до32КиБ; изменившаяся во время скачивания история требует повтора.

Ручной тест может прервать сессии. Watchdog сохраняет default/native/reserve ID+revision, восстанавливает только допустимые идентичности и не переигрывает более новый выбор. Восстановленный proxy-процесс принадлежит времени жизни службы, а не короткой probe. Восстановление режима не возвращает уже оборванные TCP/игровые сессии.

## Kernel-квалификация перед образом

ci/session-continuity.py запускается только в disposable Linux CI и создаёт собственные network namespaces. Production Build и SelectionBatch задают nft, правила и таблицы маршрутизации. Veth эмулируют AWG/proxy egress: TCP/UDP продолжают обмен по старому proxy при возврате default на AWG; новые соединения идут на AWG; повторный переход использует прежний proxy, процесс, интерфейс и маршруты. Отдельная намеренно ошибочная WAN-маршрутизация подтверждает блокировку production kill switch счётчиком drop. Отсутствие инструментов, чужой source commit или неполный receipt запрещают выпуск .bin. Veth-проверка не подтверждает реальные туннели или железо.
